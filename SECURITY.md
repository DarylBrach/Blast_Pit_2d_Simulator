# Security

The simulator is offline: it contains no network client or subprocess execution. Spawned workers run only trial tasks and the parent process alone writes governed artifacts. NPZ checkpoints are loaded with pickle disabled and archive/member/metadata limits. Experiment IDs are restricted and resolved beneath the artifact root. Atomic temporary-file replacement is used for checkpoints and JSON evidence.

The approval JSON is a local authorization record, not a signature. The application is not an OS sandbox; run it using a dedicated account or VM if operating-system isolation is required. Do not run untrusted modified simulator source. Windows junction/reparse-point enforcement remains an operating-system deployment responsibility; keep the installation and artifact root owner-writable only.

The audit namespace is deterministic from the master seed and therefore lifecycle-held, not confidential. The current release path also relies on operator verification that the planned generation count is complete. Use trusted local storage; stale audit-lock recovery and stronger multi-file transaction/approval controls remain explicit limitations.

Report suspected artifact tampering by retaining the complete experiment directory and comparing its SHA-256 manifest before further execution.

v36-specific checkpoint, approval, audit, archive-export, and release boundaries are documented in [docs/V36_SECURITY.md](docs/V36_SECURITY.md). The scoped v36 approval is local and unsigned; it cannot override a failed terminal comparison.

v37-specific robustness, committed-audit-seed, specialist-bank, and three-way comparison boundaries are documented in [docs/V37_SECURITY.md](docs/V37_SECURITY.md).

The Codex improvement controller adds a local agentic surface. Codex is constrained to a candidate worktree with workspace-write sandboxing, noninteractive approval rejection, a retained and expiring parent human authorization, delegated development-only fixture authority, a two-file Git and raw-filesystem allowlist, forbidden-code scanning, full tests, trusted scoring, and branch-only retention. Codex receives a minimal environment and secret values are redacted from retained streams. Pre/post main and production-artifact inventories prove the non-modification result, and a recursive SHA-256 manifest seals each completed evidence bundle. These controls are defense in depth, not an OS sandbox: the Windows elevated workspace backend can execute processes, and application-level scanning cannot replace a disposable low-privilege VM when stronger containment is required. The Codex API is the explicit network exception; candidate simulator code is not authorized for network access. The controller never receives production release authority or records Codex credentials intentionally.

The eight-hour launcher requires a clean Git worktree, captures dependency and input hashes, disables Ollama, uses zero automatic retries, and scopes its kill switch to one experiment. These controls improve provenance but do not create an OS sandbox. Do not place credentials in runner environment overrides or evidence; use a dedicated low-privilege account or VM for stronger isolation.

Controller v2.2 makes every builder, remediator, specialist, and final-QA model role tool-less: roles receive bounded inline packets and return schema-validated JSON, without shell, web, app, MCP, plugin, or filesystem tools. The controller alone parses and applies an allowlisted patch through the Windows write boundary. Every candidate-controlled Python command—compile, focused and complete tests, training, and trusted scoring—runs in an authorization-bound Linux Docker container. The Windows audit guard remains defense in depth and is not the candidate hard boundary.

Controller v2.1 durably snapshots the disposable lease-root SDDL, discovers the sandbox restricted SID by exact access-rule multiset comparison, writes `APPLYING` before mutation, and adds only an inheritance-only `DELETE` allow rule for descendants. It does not grant deletion of the lease root, `WRITE_DAC`, `WRITE_OWNER`, or authority outside the lease. A kernel-held controller lock serializes startup, recovery, and execution. Each lease retains a non-candidate-writable helper copy keyed by the authorization-bound hash, so a later checkout upgrade cannot strand recovery. Startup and emergency paths recover incomplete WAL records; the exact original SDDL must be restored and verified before the production guard, evidence seal, or publication. Recovery successes and failures receive their own sealed manifest, recovery decision, hash-chain ledger record, and latest hazard pointer. Failure to prove restoration blocks publication and normal startup.

The Docker hard boundary is fixed and fail-closed: immutable image `sha256:ebecafb90288df12553cb8b66e0bc2a3ce325513a19f65e40e5ce9e526db0698`, whose build inputs and package SBOM are recorded by `candidate_image_attestation_v1.json`. The authorization separately hash-binds that attestation, the runtime policy, canary, controller, and launch surfaces. The image is Linux/amd64 and non-root; runtime uses `--network none`, a read-only root filesystem, all capabilities dropped, no-new-privileges and builtin seccomp, private cgroup and IPC namespaces, bounded process/CPU/memory/file-descriptor limits, and no devices or image pulls. Exactly one host bind is permitted: the disposable workspace mounted read-only. Writable `/tmp` and `/output` are independent 256 MiB tmpfs mounts.

Candidate output cannot write through the workspace bind. Training artifacts cross only through a trusted bounded stdout exporter. The controller accepts only a bounded manifest with safe relative paths, per-file SHA-256, and base64 content, verifies every field and aggregate limit, then materializes retained output outside candidate control. Container-native probes cover sockets, raw sockets, mount, native process containment, host reads, and root-filesystem writes. Docker daemon, kernel, and administrator compromise remain outside this boundary.

Fold B development evidence is disclosed only after write roles end; final Fold C is held out for root adjudication. Neither fold is the terminal production audit. The local ledger binds sealed run hashes but remains on the same machine and is not an external signature or transparency service. No v2 record grants automatic push, merge, promotion, terminal audit, export, or release authority.
